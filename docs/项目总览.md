## 二、关键发现与决策

### 发现 1：参考代码是空的
`实训2代码/diabetesAssistant/` 下 13 个文件**全部为 0 字节**，只提供了目录结构约定，没有任何实现。因此本项目的实现不依赖该目录，仅参考其"关注点分离"思路。

### 发现 2：原代码 AI 能力为 0
全项目 `fetch` 调用数为 **0**，8 个核心 AI 任务（Dify 工作流/聊天助手/智能体）一个都没接，仅存 2 处 `alert('...实际项目中将调用Dify工作流API')` 占位。

### 发现 3：一个隐藏的功能性 Bug
`index.html` 登录后写入 `isAdmin`，而 `personal.html` 读取 `role === 'admin'` —— **字段名不一致导致管理员登录后永远看不到管理入口**。已统一为 `role: 'user' | 'admin'`。

### 核心决策：双模式运行
同时满足"必须接入 Dify"与"必须可直接运行"两个看似冲突的要求：

```
js/config.js 未配置 Key ──► js/mock-engine.js（本地规则引擎，离线可用）
js/config.js 已配置 Key ──► Dify HTTP API（Workflow / Chatflow / SSE）
                             └─ 请求失败 ──► 自动降级到本地引擎 + Toast 提示
```

另有两项设计取舍：
- **不采用 Tailwind**（参考骨架用了 `@tailwind` 指令但工程无构建链，离线会失效）→ 改用纯 CSS 设计系统，保证零依赖运行
- **不采用 `main/` 二级目录** → 13 个页面扁平化，更利于静态部署与 Nginx 配置
