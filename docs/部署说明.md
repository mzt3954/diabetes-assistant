# 部署说明

> 对应课程「四、项目部署与测试」环节：将前端页面部署到 Nginx 服务器并成功访问。

---

## 一、部署形态

本项目为**纯静态站点**（HTML + CSS + 原生 JS），零构建、零运行时依赖，可直接由任意静态服务器托管。

```
浏览器 ──► Nginx（静态文件 + /v1 反向代理）──► Dify（可选）
```

---

## 二、方式一：Nginx 部署（课程要求）

### 1. 安装 Nginx

**Windows**
```powershell
# 下载 nginx-1.24.x.zip 解压到 D:\nginx，然后：
cd D:\nginx
start nginx          # 启动
nginx -s reload      # 重载配置
nginx -s stop        # 停止
```

**Linux / macOS**
```bash
# Ubuntu / Debian
sudo apt update && sudo apt install -y nginx
# CentOS / RHEL
sudo yum install -y nginx
# macOS
brew install nginx
```

### 2. 部署文件

将 `ai/` 目录整体拷贝到服务器：

```bash
# Linux
sudo mkdir -p /var/www/diabetes-assistant
sudo cp -r ai/* /var/www/diabetes-assistant/
sudo chown -R www-data:www-data /var/www/diabetes-assistant
```

Windows 下可直接使用项目根目录的 `nginx.conf` 作为站点配置片段。

### 3. 配置 Nginx

使用项目根目录的 `nginx.conf`（完整配置见该文件），核心片段：

```nginx
server {
    listen       80;
    server_name  localhost;
    server_tokens off;

    root   /var/www/diabetes-assistant;
    index  index.html;

    # 静态资源缓存
    # ⚠️ 本 location 有自己的 add_header，父级安全头不会继承，
    #    因此必须再 include 一次安全头片段（nginx add_header 继承陷阱）
    location ~* \.(css|js|png|jpg|jpeg|gif|svg|ico|woff2?)$ {
        include snippets/security-headers.conf;
        expires 7d;
        add_header Cache-Control "public, immutable" always;
    }

    # HTML 不缓存，保证更新即时生效
    location ~* \.html$ {
        include snippets/security-headers.conf;
        add_header Cache-Control "no-cache, must-revalidate" always;
    }

    # SPA 式回退：任何未命中的路径都回退到 index.html
    location / {
        include snippets/security-headers.conf;
        try_files $uri $uri/ /index.html;
    }

    # Dify 反向代理（隐藏 API Key，解决 CORS）
    location /v1/ {
        proxy_pass         http://127.0.0.1:8080/v1/;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   Authorization     "Bearer app-你的密钥";
        proxy_set_header   Connection        "";     # SSE 必需
        proxy_buffering    off;                       # SSE 必需
        proxy_cache        off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        include snippets/security-headers.conf;
    }

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;
}
```

> **`snippets/security-headers.conf` 必须一起部署**（放在 nginx 配置目录下，
> 路径与 `nginx.conf` 里的 `include` 一致），否则 `nginx -t` 会报文件不存在。
> 它包含 CSP、`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、
> `Permissions-Policy` 五个安全头。

> **为什么每个 location 都要 include？**
> nginx 的 `add_header` 不是「子级覆盖父级、其余继承」的语义：只要某个
> `location` 内出现了**任意一条** `add_header`，父级（server/http）的
> `add_header` 就**全部不再继承**。旧配置把安全头写在 server 级、又在两个
> location 里写 `Cache-Control`，结果静态资源与 HTML 响应上的安全头被静默丢弃。

生产环境建议启用 `nginx.conf` 中的 **443 站点**（已含 TLS 配置、HSTS 与
HTTP→HTTPS 301 跳转），并在 `js/config.js` 中设置 `proxyMode: true`。

### 4. 校验与启动

```bash
nginx -t                 # 语法校验，须输出 syntax is ok / test is successful
sudo nginx -s reload     # 重载
```

浏览器访问 `http://localhost` 或 `http://<服务器IP>`，看到登录页即部署成功。

验证安全头是否生效：

```bash
curl -sI http://localhost/index.html | grep -iE "content-security-policy|x-content-type|x-frame|referrer"
```

## 三、方式二：快速预览（开发调试）

```bash
cd ai
npx http-server -p 8080 -c-1     # Node
python -m http.server 8080       # Python
```
访问 <http://localhost:8080>

> ⚠️ 不要用 `file://` 协议做正式验证——部分浏览器对 `file://` 下的存储与跨域限制更严。双击 `index.html` 可用于功能体验，但部署验收请用 HTTP 服务。

## 四、方式三：容器化部署（可选）

`Dockerfile`：

```dockerfile
FROM nginx:1.25-alpine
COPY . /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

```bash
docker build -t diabetes-assistant .
docker run -d -p 8080:80 --name dpa diabetes-assistant
```

## 六、常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| 页面 404 | `root` 路径配置错误 | 检查 `root` 指向 `ai/` 目录，用绝对路径 |
| 刷新子页面 404 | 未配置 `try_files` | 加上 `try_files $uri $uri/ /index.html;` |
| 样式/脚本未加载 | MIME 类型错误 | 确认 `include mime.types;` 存在 |
| AI 功能提示"离线演示模式" | 未配置 Dify | 参见 `docs/Dify应用配置指南.md` |
| 流式输出无效果 | Nginx 缓冲了 SSE | `proxy_buffering off;` + `proxy_cache off;` |
| 接口 CORS 报错 | 跨域未放行 | 配置 Dify 的 CORS 或用 Nginx 同源代理 |
| 中文乱码 | 缺少 charset | 配置 `charset utf-8;` |

## 八、安全加固建议

1. **不要在公网明文暴露 Dify API Key**：走 Nginx 反向代理注入，并在 `js/config.js` 中设置 `proxyMode: true`、`apiKey` 全部留空
2. 启用 HTTPS 与 HSTS：`certbot --nginx -d your-domain.com`，并启用 `nginx.conf` 的 443 站点段
3. 安全响应头统一走 `snippets/security-headers.conf`（CSP / nosniff / X-Frame-Options / Referrer-Policy / Permissions-Policy），**每个 location 都要 include**（见第 3 节的继承陷阱说明）
4. **口令**：前端已用 `js/crypto.js` 做加盐 + 1000 轮迭代哈希，localStorage 中不再出现明文。但这只是"演示数据不落明文"，**不是服务端鉴权**——正式上线必须把用户体系迁到服务端，用 bcrypt/argon2 校验，前端哈希不能替代
5. 关闭 `server_tokens`，隐藏 nginx 版本号（`nginx.conf` 已配置）
6. 限制请求体大小（`client_max_body_size 2m;`）与开启访问频率限制
